# CRAI Enterprise Frontend v4

A modular React/Vite SaaS-style frontend for CRAI — Adaptive Edge Agricultural Intelligence.

## Architecture

- `src/App.jsx` — application composition and navigation state
- `src/hooks/useCRAI.js` — backend workflow, analysis, sensor acquisition, local field memory
- `src/services/api.js` — FastAPI client
- `src/components/common/UI.jsx` — reusable UI primitives and icons
- `src/components/layout/Shell.jsx` — enterprise navigation shell
- `src/components/map/FarmMap.jsx` — SVG precision-farming map and zone interaction
- `src/pages/*` — Overview, Observe, Intelligence, Sensors, History, Reports, Settings
- `src/utils/crai.js` — timestamps, freshness, risk and local-history helpers

## Backend contract

Default API: `http://127.0.0.1:8000`

Routes used:
- GET `/api/health`
- GET `/api/ai/status`
- GET `/api/field-sensors/readings`
- GET `/api/field-sensors/requests/pending`
- POST `/api/field-sensors/requests`
- POST `/api/field-sensors/readings`
- POST `/api/analysis/image`

## Run

```powershell
npm install
npm run build
npm run dev
```

Run the backend separately:

```powershell
cd ..\backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

The frontend keeps deterministic CRAI risk/decision authoritative. Any LLM advisory is presented as explanation-only.


## Hardware integration contract
The frontend expects physical ESP32 readings at `POST /api/field-sensors/readings` with `source: REAL`, `device_id: CRAI-ESP32-01`, `farm_id`, `zone_id`, and `soil_moisture`/`temperature`/`humidity`. Freshness is evaluated with the CRAI 15-minute policy. The frontend never treats SIMULATED readings as physical hardware evidence. The ESP32 firmware should use the laptop LAN IP, not localhost/127.0.0.1, and should claim pending requests before posting a REAL reading.

Advisory language is generated by the backend analysis endpoint using the selected `advisory_language`; changing language on an existing result uses **Regenerate advisory** and does not create a duplicate history record.
